Problem

Analysts need a clear way to review traffic risk, explanations, and the limits of a model's evidence.

Method and dataset

Argus evaluates next-window network risk on historical UNSW-NB15 flow data, using one-second windows and five windows of recent features. It compares Random Forest, current-window and lagged logistic regression, and an oracle persistence diagnostic.

Dataset: Moustafa, N. and Slay, J. (2015), UNSW-NB15, MilCIS. Lab benchmark traffic is not live production traffic.

Split and limitations

The pipeline orders windows chronologically for a 70% training, 10% validation, and 20% test split. Thresholds maximize validation F1. Window-size selection consulted label counts including test; this is a limitation. The stored RF threshold is zero and flags all test windows. Risk scores are not calibrated probabilities.

Website inspection

The Website view inspects the top-level page only, on your request. Its rule indicator adds 40 points for non-loopback HTTP, 30 for HTTP references on HTTPS, 35 for password forms targeting HTTP, and 20 for other forms targeting HTTP, capped at 100. Third-party origins and HTTP errors are measurements, not attack findings. Zero does not mean safe.

Browser-internal pages, extension pages, the extension store, and file URLs are unsupported. Cross-origin timing may hide bytes and status. This cannot determine whether a server is compromised.

Website performance measurements

The current website report measures retained completed resource requests, median/P95 durations, available HTTP error rate, load timing, and visible transfer. Its demonstration budgets are 3,000 ms page load, no observed requests over 1,000 ms, 2,048 KiB visible transfer, and 100 retained HTTP resources. These are explicit local budgets, not industry standards, ML scores, precision, or recall. Matching evidence can legitimately yield matching rule scores on different websites.

Explainability and analyst notes

SHAP explains selected Random Forest benchmark windows. Stage labels are evaluation-only. Optional Gemma runs through local Ollama; a Template fallback keeps notes available. Notes use the backend default model, independently of the selector. Website snapshots are never sent to the API or Gemma.

Claims policy

This is a benchmark console and a passive browser inspector, not a production intrusion detector, vulnerability scanner, or arbitrary-website attack predictor. Future live model use requires an authorized collector, matching flow features, and fresh validation.
